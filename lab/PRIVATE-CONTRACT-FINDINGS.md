# DLSSNR private contract findings

This note records the feature-18 contract probes performed against the local
`nvngx_dlssnr.dll` 310.8 package. The tests are intentionally isolated from the
ReShade addon and do not imply that these private interfaces are stable.

## Runtime parameter callback

`NVSDK_NGX_SetRuntimeParamsCallback` accepts a callback with this recovered x64
ABI:

```cpp
bool callback(uint32_t feature_id, uint32_t count, RuntimeParamRecord *records);
```

Feature 18 supplies eight 24-byte records. Correlating the callback's writes
with the feature's parameter parser gives this mapping:

| ID | Runtime field | Encoding |
|---:|---|---|
| 0 | Enabled | Boolean |
| 1 | LocalToneStrength | Double |
| 2 | LocalStructureStrength | Double |
| 3 | Intensity | Double |
| 4 | Style | Unsigned integer |
| 5 | UseAutoMask | Boolean |
| 6 | SkinStructureStrength | Integer divided by 1000 |
| 7 | ScalingRatio | Integer divided by 1000 |

The DLL reads the ordinary `DLSSNR.ScalingRatio` parameter but initializes the
live evaluation value to `1.0` before polling this callback. Consequently, the
callback is the only observed path that can alter the live scaling field.

The laboratory's `--runtime-scale` option fills record 7 and returns `true`.
Values from `0.25` through `2.0` were accepted and evaluation succeeded, but
all six runs produced the same checksum and wrote only the input-sized
upper-left quadrant of a 2x output allocation. The machine-readable output is
generated by `run-runtime-scale-probe.ps1` as `runtime-scale-probe.json`.

## Stats callback

`DLSSNRGetStatsCallback` uses the standard one-parameter NGX stats ABI. It
returns success for this package and reports:

- `SizeInBytes`: 0
- optimization level: 40
- development snippet branch: false

It does not advertise output dimensions, supported scaling ranges, or an
upscaling mode.

## Style, preset, and quality matrix

`run-private-contract-matrix.ps1` evaluates 72 direct-NR cases: three hint
presets, four styles, and all six NGX performance-quality values, using a
320x180 active input and a 640x360 output allocation.

- All 72 features created and evaluated successfully.
- All 72 wrote exactly 25% of the output: the input-sized upper-left quadrant.
- No case validated direct upscaling.
- Max Performance, Balanced, Max Quality, Ultra Quality, and DLAA resolve to a
  provider scaling ratio of `1.0`.
- Ultra Performance is rejected by `DLSSNRComputeScalingRatioCallback` with
  `UnsupportedParameter`.
- Changing `DLSSNR.Hint.Render.Preset` from 1 through 3 does not change the
  output checksum in this deterministic test.
- `DLSSNR.Style` values 0, 1, and 2 produce three distinct checksums. Style 3
  aliases style 2. This strongly indicates that Style, not Hint.Render.Preset,
  selects the package's three effective NR looks/models.

The generated detailed result is `private-contract-matrix.json`.

## Current conclusion

This package has a live scaling control, but it does not make feature 18 write
a larger image. Within every discovered creation, evaluation, callback, style,
preset, and quality path, NR remains an input-resolution image transformation.
Native-resolution reconstruction still requires the separate DLSS Super
Resolution feature.
